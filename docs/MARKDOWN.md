# ChAoS MVC Markdown Reference

This document describes the Markdown syntax implemented by the ChAoS MVC `render_md` library.

The renderer provides a deliberately small Markdown dialect for documentation, changelogs, internal pages, and other ChAoS MVC content.

It implements selected standard Markdown and GitHub-style features while retaining several ChAoS-specific extensions.

> Keep it small, deterministic, and easy to use.

---

## Headings

Headings from level one through level six are supported.

```text
# Heading 1
## Heading 2
### Heading 3
#### Heading 4
##### Heading 5
###### Heading 6
```

These are rendered as the corresponding HTML heading elements.

```html
<h1 id="heading-1">Heading 1</h1>
<h2 id="heading-2">Heading 2</h2>
<h3 id="heading-3">Heading 3</h3>
<h4 id="heading-4">Heading 4</h4>
<h5 id="heading-5">Heading 5</h5>
<h6 id="heading-6">Heading 6</h6>
```

---

## Heading Anchors

Headings automatically receive URL-friendly IDs.

For example:

```text
## Authority Doctrine
```

renders with an anchor similar to:

```html
<h2 id="authority-doctrine">Authority Doctrine</h2>
```

This permits direct links to document sections.

Example:

```text
/docs/details/codex#authority-doctrine
```

Heading anchors are generated by:

- Converting text to lowercase
- Removing formatting punctuation
- Replacing spaces with hyphens
- Removing unsupported characters

For example:

```text
## Colors of Grade
```

becomes:

```text
#colors-of-grade
```

---

## Bold Text

Use two asterisks around text to render it as bold.

```text
**This text is bold.**
```

Rendered as:

```html
<strong>This text is bold.</strong>
```

Example:

```text
ChAoS MVC keeps the **Core protected**.
```

---

## Italic Text

Italic text may use either asterisks or underscores.

```text
*This text is italic.*
```

or:

```text
_This text is italic._
```

Rendered as:

```html
<em>This text is italic.</em>
```

---

## Strikethrough

Double tildes use GitHub-style strikethrough behavior.

```text
~~This text is deprecated.~~
```

Rendered as:

```html
<del>This text is deprecated.</del>
```

Example:

```text
The ~~old method~~ new method should be used.
```

### Compatibility Note

Earlier versions of the ChAoS MVC Markdown renderer used double tildes for small text.

That behavior has changed.

Double tildes now represent strikethrough:

```text
~~strikethrough~~
```

Small text now uses the ChAoS extension:

```text
{small}small text{/small}
```

---

## Small Text

Small text uses a controlled ChAoS Markdown extension.

```text
{small}This text is small.{/small}
```

Rendered as:

```html
<small>This text is small.</small>
```

Example:

```text
{small}Additional explanatory information.{/small}
```

---

## Colored Text

ChAoS MVC provides a controlled named-color extension.

Syntax:

```text
{color:name}Text{/color}
```

Example:

```text
{color:red}Red text{/color}
```

Another example:

```text
{color:huntergreen}Hunter Green{/color}
```

The Markdown renderer does not accept arbitrary CSS values from Markdown.

Only approved color names are supported.

### Supported Colors

| Markdown Name | Color |
| --- | --- |
| `grey` | Grey |
| `gray` | Gray |
| `white` | White |
| `huntergreen` | Hunter Green |
| `purple` | Purple |
| `red` | Red |
| `black` | Black |
| `brown` | Brown |
| `blue` | Blue |
| `pink` | Pink |

Example:

```text
- None (Seeker)
- {color:grey}Grey{/color} (Neophyte)
- White (Initiate)
- {color:huntergreen}Hunter Green{/color} (Adeptus-minor)
- {color:purple}Purple{/color} (Priestess)
- {color:red}Red{/color} (Adeptus)
- {color:black}Black{/color} (Prioress)
- {color:brown}Brown{/color} (Adeptus-Major)
- {color:blue}Blue{/color} (Soror)
- {color:pink}Pink{/color} (Madam)
```

A document does not have to apply a color merely because the color exists.

For example, white text may be deliberately left uncolored when used on a light theme.

## Links

Links use standard Markdown link syntax.

```text
[Link Text](URL)
```

Example:

```text
[Downloads](/downloads)
```

External link:

```text
[GitHub](https://github.com/)
```

Email link:

```text
[Contact](mailto:example@example.com)
```

### Supported URL Types

The renderer permits links using:

```text
https:
http:
mailto:
```

It also permits root-relative internal URLs:

```text
/downloads
/releases
/docs
```

For example:

```text
[Downloads](/downloads)
```

or:

```text
[Releases](/releases)
```

### Unsafe URLs

Unsafe URL schemes are rejected by the renderer.

For example:

```text
[Unsafe](javascript:alert(1))
```

must not become an executable JavaScript link.

This restriction protects Markdown-rendered content from unsafe URL schemes.

---

## Automatic URL Links

HTTP and HTTPS URLs may be written directly without explicit Markdown link syntax.

Example:

```text
https://chaos-mvc.org
```

The renderer automatically converts the URL into a clickable link.

Example:

```text
Project repository:
https://github.com/stnlabz/chaos-mvc
```

Explicit Markdown links are still preferred when descriptive link text improves readability.

```text
[ChAoS MVC Repository](https://github.com/stnlabz/chaos-mvc)
```

---

## Inline Code

Inline code uses a single backtick.

```text
`CHAOS_VERSION`
```

Rendered as:

```html
<code>CHAOS_VERSION</code>
```

Example:

```text
The installed version is defined by `CHAOS_VERSION`.
```

Inline code is protected from other Markdown transformations.

For example:

```text
`password_hash()`
```

will remain code and will not interpret underscores as italics.

---

## Fenced Code Blocks

Code blocks use triple backticks.

````text
```
Example code
```
````

A language identifier may be placed after the opening fence.

````text
```php
echo 'Hello, ChAoS MVC';
```
````

The renderer uses the language identifier when generating the code block class.

For example:

````text
```php
echo 'Hello';
```
````

is rendered using a class corresponding to:

```text
code-php
```

This allows site CSS to provide language-specific presentation where desired.

### Example: PHP

````text
```php
<?php

echo 'ChAoS MVC';
```
````

### Example: JSON

````text
```json
{
    "name": "ChAoS MVC",
    "version": "1.1.10"
}
```
````

### Example: C

````text
```c
#include <stdio.h>

int main(void)
{
    printf("ChAoS MVC\n");
    return 0;
}
```
````

Content inside fenced code blocks is protected from normal Markdown processing.

## Blockquotes

A blockquote begins with `>`.

```text
> Keep it small, deterministic, and easy to use.
```

Multiple quoted lines may be written as:

```text
> Protect the Core.
> Keep behavior deterministic.
> Grow outward.
```

## GitHub-Style Alerts

The renderer supports selected GitHub-style alert blocks.

Supported alert types are:

```text
NOTE
TIP
IMPORTANT
WARNING
CAUTION
```

### Note

```text
> [!NOTE]
> This is additional information.
```

### Tip

```text
> [!TIP]
> This may make the task easier.
```

### Important

```text
> [!IMPORTANT]
> This information should not be ignored.
```

### Warning

```text
> [!WARNING]
> This action may have consequences.
```

### Caution

```text
> [!CAUTION]
> Proceed carefully.
```

Alerts are rendered with classes that allow themes to provide their own presentation.

For example:

```text
markdown-alert
markdown-alert-note
markdown-alert-warning
```

## Unordered Lists

Unordered lists may use `-`, `*`, or `+`.

```text
- Controllers
- Models
- Views
```

The following is also valid:

```text
* Controllers
* Models
* Views
```

And:

```text
+ Controllers
+ Models
+ Views
```

---

## Nested Lists

Lists may be nested using indentation.

Four spaces per level are recommended.

```text
- Parent
    - Child
        - Grandchild
    - Another child
- Another parent
```

Example:

```text
- Rotation rules
    - Rotation of the Elemental Priestess is essential.
        - Rotation should be determined between the parties involved.
            - Alternating duties in a flip-flop fashion is recommended.
```

Nested ordered lists are also supported.

```text
1. First level
    1. Second level
        1. Third level
```

The renderer determines nesting from indentation.

Four spaces per level remain the recommended style for ChAoS MVC documentation.

---

## Ordered Lists

Ordered lists use a number followed by a period.

```text
1. Controller
2. Model
3. View
```

Ordered lists may also be nested.

```text
1. Application
    1. Controller
    2. Model
    3. View
2. User
    1. Modules
    2. Themes
```

---

## Task Lists

GitHub-style task lists are supported.

Unchecked task:

```text
- [ ] Pending
```

Checked task:

```text
- [x] Complete
```

Uppercase `X` is also accepted:

```text
- [X] Complete
```

Example:

```text
- [x] Design complete
- [x] Human review complete
- [ ] Release package
- [ ] Publish release
```

Task checkboxes are rendered as disabled display controls.

They represent document state and are not interactive form controls.

Nested task lists may also be used.

```text
- [x] Core work
    - [x] Router
    - [x] Controller
    - [ ] Documentation
```

## Tables

Markdown tables are supported.

Example:

```text
| Name | Version |
| --- | --- |
| ChAoS MVC | 1.1.10 |
| Support | 1.0.2 |
```

Tables contain:

- A header row
- A separator row
- Zero or more body rows

Example:

```text
| Grade | Color |
| --- | --- |
| Seeker | None |
| Neophyte | Grey |
| Initiate | White |
```

### Table Alignment

Column alignment may be specified with colons.

Left aligned:

```text
| Name |
| :--- |
| ChAoS MVC |
```

Centered:

```text
| Name |
| :---: |
| ChAoS MVC |
```

Right aligned:

```text
| Name |
| ---: |
| ChAoS MVC |
```

Combined example:

```text
| Name | Status | Version |
| :--- | :---: | ---: |
| Support | Stable | 1.0.2 |
| Security | Active | 1.0.0 |
```

A literal pipe inside a cell may be escaped:

```text
\|
```

---

## Definition Lists

Definition lists provide a compact way to define terms.

Syntax:

```text
Term
: Definition
```

Example:

```text
Core
: The protected ChAoS MVC framework layer.

Module
: Installation-owned functionality under the user module boundary.
```

Multiple definitions may follow one term.

```text
Authority
: Permission established by policy or role.
: Authority does not automatically imply implementation access.
```

Definition lists are rendered using:

```html
<dl>
<dt>Term</dt>
<dd>Definition</dd>
</dl>
```

---

## Footnotes

Footnotes may be used to move supporting material out of the primary text.

A footnote reference uses:

```text
[^1]
```

The matching definition uses:

```text
[^1]: Supporting information.
```

Example:

```text
This doctrine has additional historical context.[^1]

[^1]: Supporting historical information belongs here.
```

The renderer places collected footnotes at the bottom of the rendered document and provides a return link to the original reference.

Footnote identifiers may contain letters, numbers, underscores, and hyphens.

Example:

```text
This statement requires qualification.[^history]

[^history]: Historical qualification goes here.
```

Footnote definitions should currently remain on a single Markdown line.

## Escaping Markdown Characters

Markdown characters may be escaped with a backslash when they should be displayed literally.

Example:

```text
\*This is not italic.\*
```

Example:

```text
\# This is not a heading.
```

Example:

```text
\- This is not a list item.
```

Example:

```text
\[This is not a link\]
```

Escaping is useful when documenting Markdown itself or when punctuation would otherwise trigger formatting.

Common escapable characters include:

```text
\
`
*
_
{
}
[
]
(
)
#
+
-
.
!
>
|
~
```

Ordinary Markdown lines are converted into HTML line breaks where applicable.


## Combining Formatting

Supported inline formatting may be combined when appropriate.

```text
Read the **current release** on the [Releases](/releases) page.
```

Another example:

```text
The `CHAOS_VERSION` constant contains the **installed Core version**.
```

Color and bold may also be combined.

```text
**{color:red}Important{/color}**
```

Task lists may contain inline formatting.

```text
- [x] **Development complete**
- [ ] Publish the `1.0.0` package
```

Table cells may contain normal inline Markdown where supported by the renderer's processing order.

## Internal ChAoS MVC Links

For pages within the same ChAoS MVC installation, root-relative links are preferred.

```text
[Home](/)
```

```text
[Downloads](/downloads)
```

```text
[Releases](/releases)
```

```text
[Certification](/certification)
```

This keeps internal documentation independent of the installation's domain name.

Heading anchors may be combined with internal links.

```text
[Jump to Security](#security)
```

or:

```text
[Authority Doctrine](/docs/details/codex#authority-doctrine)
```

## Images

Markdown image syntax is not currently implemented.

Standard Markdown commonly uses:

```text
![Alt Text](/path/to/image.png)
```

Do not rely on this syntax when writing content for the ChAoS MVC Markdown renderer.

Image handling should remain an explicit future feature if ChAoS MVC develops a demonstrated requirement for it.

## Raw HTML

The Markdown renderer does not provide raw HTML as a general Markdown feature.

For example:

```html
<strong>Raw HTML</strong>
```

should not be used as a substitute for supported Markdown syntax.

Use:

```text
**Bold text**
```

instead.

Markdown content is HTML-escaped before supported transformations are applied.

This is intentional.

---

## Security Behavior

Markdown content is treated as content rather than trusted executable markup.

The renderer escapes content before applying supported Markdown transformations.

This provides a controlled Markdown surface rather than allowing arbitrary HTML execution.

### Link Validation

Markdown links are validated before becoming HTML links.

Accepted link forms include:

```text
https://example.com
http://example.com
mailto:user@example.com
/internal/path
```

Unsafe or unsupported schemes are rejected.

Examples include:

```text
javascript:
data:
```

These must not be treated as executable Markdown links.

### Controlled Color Values

Color markup accepts only explicitly approved names.

For example:

```text
{color:red}Allowed{/color}
```

Arbitrary values are not accepted through Markdown.

For example, the renderer does not treat arbitrary CSS supplied by a document as trusted style declarations.

### Code

Inline and fenced code content is rendered as code rather than executable markup.

For example:

````text
```html
<script>alert('Nope');</script>
```
````

The contents of the code block are displayed as code.

### Task Lists

Task list checkboxes are rendered disabled.

Markdown cannot create interactive form submissions through task syntax.

## PHP API

The Markdown renderer is provided by the `render_md` class.

### Create the Renderer

```php
$renderer = new render_md();
```

### Render Markdown

Markdown text can be rendered using:

```php
$renderer = new render_md();

echo $renderer->markdown($markdown);
```

Example:

```php
$renderer = new render_md();

$markdown = '**ChAoS MVC**';

echo $renderer->markdown($markdown);
```

### Render a Markdown File

A Markdown file can be rendered using:

```php
$renderer = new render_md();

$renderer->markdown_file($path);
```

The supplied path identifies the Markdown document to be rendered.

## ChAoS Extensions

The renderer includes features that are not standard Markdown or are intentionally controlled by ChAoS MVC.

### Small Text

```text
{small}Small text{/small}
```

### Named Colors

```text
{color:red}Red{/color}
```

```text
{color:huntergreen}Hunter Green{/color}
```

These extensions exist because ChAoS MVC has demonstrated uses for them.

They should remain controlled and deterministic.

---

## GitHub-Style Features

The current renderer includes several features inspired by GitHub Flavored Markdown.

These include:

- Tables
- Task lists
- Strikethrough
- Automatic HTTP and HTTPS links
- Nested lists
- Heading anchors
- GitHub-style alerts

It also includes useful Markdown-adjacent functionality such as:

- Definition lists
- Footnotes
- Markdown character escaping
- Controlled named colors
- Controlled small text

The renderer is not intended to provide complete byte-for-byte GitHub Flavored Markdown compatibility.

---

## Currently Unsupported or Limited Syntax

The ChAoS MVC Markdown renderer intentionally remains smaller than a complete Markdown ecosystem.

Current limitations include:

- Markdown image syntax is not implemented
- Raw HTML is not enabled
- Footnote definitions are single-line
- Complete CommonMark behavior is not guaranteed
- Complete GitHub Flavored Markdown compatibility is not guaranteed
- Duplicate heading names are not automatically assigned GitHub-style numeric suffixes
- Complex multiline table cells are not supported
- Complex multiline definition bodies are not supported
- Arbitrary CSS colors are intentionally rejected
- Interactive Markdown form controls are not supported

Unsupported syntax may be rendered as ordinary text rather than interpreted as Markdown.

---

## Design Philosophy

The ChAoS MVC Markdown renderer intentionally does not attempt to become a complete Markdown ecosystem.

Its purpose is to provide the formatting needed by ChAoS MVC while remaining:

- Small
- Deterministic
- Understandable
- Easy to use
- Easy to maintain
- Safe for controlled content rendering

Additional Markdown features should be added because ChAoS MVC has a demonstrated requirement for them, not simply because another Markdown implementation provides them.

The renderer may borrow useful conventions from GitHub while retaining ChAoS-specific behavior where that behavior serves the framework.
